# Lecturer Fase 1 Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ubah backend absensi dari QR-per-sesi menjadi QR-statis-per-jadwal dengan ON/OFF manual dosen (fase 1 desain dosen).

**Architecture:** Migrasi Postgres baru (kolom sesi + tabel `attendance_sessions` + scoping lecturer) lalu rombak 2 Edge Function dan tambah 1 function baru. Semua tulis tetap via service role di function; RLS tetap; zona waktu `Asia/Jakarta` eksplisit.

**Tech Stack:** Supabase (Postgres, RLS, Edge Functions Deno), Deno test + mock.

**Spec:** `docs/superpowers/specs/2026-10-13-lecturer-attendance-design.md` — plan ini mengimplementasikan bagian "Fase 1 (build ini)" + "Resolusi builder-check". Dashboard web ikut plan terpisah.

## Global Constraints

- Pesan error ke client Bahasa Indonesia, generik (tidak membocorkan eksistensi user/NIM/jadwal).
- Tidak ada emoji di string user-facing manapun.
- Penentuan status/waktu dalam zona `Asia/Jakarta` eksplisit, tidak pernah jam runtime-lokal.
- Semua tulis DB dari client dilarang; hanya Edge Function (service role) yang menulis `attendance_*`, `qr_tokens`, `attendance_codes`.
- Token QR tidak pernah berubah per jadwal; yang berubah hanya status + expiry sesi.
- Submit yang diterima = status `HADIR` (aturan TERLAMBAT tidak dipakai; kolom `late_threshold_minutes` diabaikan, tidak dihapus).

## Review Focus

- Absensi minggu kedua untuk schedule + student yang sama → diharapkan sukses (sesi baru), bukan 409 duplicate. (Test: Task 4, submit ke 2 sesi berbeda.)
- Submit 1 detik setelah `session_expires_at` lewat → diharapkan ditolak + sesi auto-OFF. (Test: Task 4, submit melewati expiry.)
- ON saat sesi sudah ON → diharapkan perpanjang expiry, bukan baris sesi ganda meledak. (Test: Task 3, ON ganda.)
- Lecturer B menyalakan jadwal milik lecturer A → diharapkan 403. (Test: Task 3, guard pemilik.)
- QR jadwal X di-submit untuk schedule_id Y → diharapkan ditolak mismatch. (Test: Task 4, token-schedule mismatch.)

### Task 3: Function set-session-state (ON/OFF)

**Files:**
- Create: `supabase/functions/set-session-state/index.ts`
- Test: `supabase/functions/tests/set_session_state_test.ts`

**Interfaces:**
- Consumes: `schedules` + `attendance_sessions` + `attendance_codes` dari Task 1; token statis dari Task 2.
- Produces: `POST set-session-state(body: {schedule_id: number, state: 'on'|'off', duration_minutes?: number}, auth: lecturer JWT pemilik) -> {state: 'on'|'off', session_id: number|null, expires_at: string|null} | {error}`. ON: `session_open=true`, `session_expires_at = server-now + duration (default 10, range 1–120)`, buat baris `attendance_sessions` baru + mirror `attendance_codes.is_active=true` (+ buat kode permanen bila belum ada); ON saat ON → perpanjang expiry sesi berjalan (tanpa baris sesi baru). OFF: `session_open=false`, tutup sesi berjalan (`closed_at=now`), mirror codes off. Guard: lecturer pemilik (403 bila bukan), jadwal arsip 404.
